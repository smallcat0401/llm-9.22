# V4 4B 最终结果

日期：2026-10-08

## 实验链路

本实验比较同一个 Qwen3.5-4B instruct starting policy 的三个阶段：

`起始策略 -> 搜索轨迹 SFT -> 可验证奖励 GRPO`

72 道冻结 test 在任何最终结果产生前已经固定，包含 36 道 V3 原测试题与 36 道经审核的 V4 扩充题。所有运行均使用 seed 937、greedy 解码和 4-bit 加载。

SFT 与 GRPO 在公司 Linux GPU 上评测；遗漏的起始策略对照随后在本机 RTX 4060 Windows 环境补测。两边使用相同公开 checkpoint 标识、数据、提示协议和解码参数，但由于硬件、Transformers/PyTorch kernel 与本地模型文件环境不同，三阶段差异应作为严格配置匹配、但非完全同机的比较。

## 主要结果

| 阶段 | Custom 严格任务成功 | Native 工具任务成功 |
|---|---:|---:|
| 起始策略 | 22/72（30.56%） | 15/72（20.83%） |
| SFT | 38/72（52.78%） | 30/72（41.67%） |
| GRPO | 36/72（50.00%） | 32/72（44.44%） |

相对起始策略：

- SFT：custom 净增 16 题（+22.22 个百分点）；native 净增 15 题（+20.83 个百分点）。
- GRPO：custom 净增 14 题（+19.44 个百分点）；native 净增 17 题（+23.61 个百分点）。

相对 SFT：

- GRPO 在 custom 主协议下降 2 题（-2.78 个百分点）。
- GRPO 在 native 诊断协议提升 2 题（+2.78 个百分点）。
- 因此没有证据支持“GRPO 稳定提高总体能力”；它产生了真实但依赖协议的行为变化。

## 协议遵循与答案正确性

### Custom 协议

| 指标 | 起始策略 | SFT | GRPO |
|---|---:|---:|---:|
| 严格任务成功 | 22/72 | 38/72 | 36/72 |
| 仅看数值 verifier 通过 | 36/72 | 38/72 | 36/72 |
| 协议错误 | 27/72 | 3/72 | 3/72 |
| 工具选择正确 | 66/72 | 72/72 | 72/72 |

Custom 下 SFT 的严格成功率提升主要来自协议错误从 27 题降到 3 题；只看最终数值正确性仅从 36 题升到 38 题。因此不能把全部 +22.22 个百分点描述为纯数学推理能力提升。

### Native 工具协议

| 指标 | 起始策略 | SFT | GRPO |
|---|---:|---:|---:|
| 调用工具 | 51/72 | 72/72 | 72/72 |
| 工具执行成功 | 51/72 | 72/72 | 72/72 |
| 工具表达式结果正确 | 19/72 | 30/72 | 32/72 |
| 最终答案正确 | 15/72 | 30/72 | 32/72 |
| Typed final 合规 | 24/72 | 47/72 | 52/72 |
| 严格任务成功 | 15/72 | 30/72 | 32/72 |

Native 结果表明 SFT 同时改善了工具调用覆盖、表达式正确性和最终结构化输出；GRPO 在这一协议上进一步带来小幅提升，但样本只有 72 题且净变化只有 2 题。

## 逐题配对变化

| 比较 | 新增正确 | 退化 | 不变 | 净变化 |
|---|---:|---:|---:|---:|
| 起始策略 -> SFT（custom） | 21 | 5 | 46 | +16 |
| 起始策略 -> GRPO（custom） | 19 | 5 | 48 | +14 |
| SFT -> GRPO（custom） | 0 | 2 | 70 | -2 |
| 起始策略 -> SFT（native） | 15 | 0 | 57 | +15 |
| 起始策略 -> GRPO（native） | 17 | 0 | 55 | +17 |
| SFT -> GRPO（native） | 2 | 0 | 70 | +2 |

SFT -> GRPO 的四个翻转均经逐题检查：custom 的两道退化分别漏掉完整征税范围和一段油价乘法；native 的两道提升分别修正路线成本组合和“每两件第二件半价”的表达式。

## 原题与扩充题

| 协议与阶段 | V3 原36题 | V4 扩充36题 |
|---|---:|---:|
| Custom 起始策略 | 12/36 | 10/36 |
| Custom SFT | 16/36 | 22/36 |
| Custom GRPO | 16/36 | 20/36 |
| Native 起始策略 | 8/36 | 7/36 |
| Native SFT | 11/36 | 19/36 |
| Native GRPO | 12/36 | 20/36 |

SFT 的净提升在 V4 扩充题上更明显，但这些题与 V3 父题共享 family，因此不能称为完全未见的新关系泛化。

## 最终结论

1. 搜索轨迹 SFT 对最终任务有明确正向作用，尤其显著改善结构化协议遵循和工具调用。
2. SFT 也改善了 native 工具表达式正确率，但 custom 的 outcome-only 增幅较小，说明数学关系理解仍是瓶颈。
3. GRPO 的总体效果不稳定：native 小幅提升，custom 小幅下降；按预先指定的 custom 主指标，应保留 SFT adapter 作为推荐 checkpoint。
4. 本项目真实完成了 `starting policy -> best-of-N search -> trajectory SFT -> GRPO/RLVR -> frozen evaluation`，但不声称 GRPO 获得稳定、广泛的能力提升。
5. 冻结 test 已经打开，之后不得使用这批题继续训练、调参或选择性重跑。若继续研究，应建立新的数据版本和未见 family 测试集。
