## 主要发现

1. 这套 validation 有区分度：既不是全部做对，也不是全部失败。
2. 分段提成已经饱和，不能单独证明训练提升；补助、商品篮变化率和公开题更能区分能力。
3. 三道公开题未调用工具且直接给出错误答案，说明“calculator 可用”不等于模型一定会正确选择工具。
4. 十条协议错误全部是 `malformed_json`。代表性失败是在多次工具调用后，把第三次工具请求、角色标记和 final JSON 混在同一输出中。
5. 工具本身没有执行失败；当前瓶颈主要是公式构造、多步交互控制和协议遵循，而不是计算器实现。

## 关于旧失败分析器

`calculator_analysis.py` 的旧逻辑只读取第一步工具结果，并假设该结果应直接等于 GT。新任务允许多步工具调用，第一步可能只是合法中间值，因此不能把其 `WRONG_TOOL_RESULT` 标签用于本次正式结论。本报告只采用最终 verifier、严格任务状态、协议状态和真实调用记录。
