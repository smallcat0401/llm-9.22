# V4 训练轨迹自检与筛选 v1

本轮只检查和筛选 **train 轨迹**，没有训练模型，也没有使用 validation/test 生成轨迹。原 214 条合并候选与原始 Best-of-8 结果保持不变。

自检范围：V4 搜索轨迹 115 条、助理编写的参考轨迹 41 条；原 V3 的 58 条核对了合并时的完整性和来源标签。对新增轨迹逐条核对题目对应、工具调用/观察值、计算器重放、最终答案与 GT、来源及 split。115 条搜索轨迹中有 104 条调用计算器一次、11 条调用两次；41 条参考轨迹均调用一次。两次调用本身不是错误。

发现一条不适合直接用于 SFT 的搜索成功轨迹：`v4-review-curriculum-v2-required-score-002`。题目要求四次分数 76、80、79、88 后，达到五次平均 79.6 所需的第五次分数。轨迹首次调用的表达式是 `(76 + 80 + 79 + 88 + 79.6 * 5) / 5 - (76 + 80 + 79 + 88)`，计算器返回 `-178.8`；之后模型改用 `79.6 * 5 - (76 + 80 + 79 + 88)`，最终答 `75`。因此它的最终结果虽然正确，整段却包含不应直接模仿的错误首步。其余十条两次调用记录没有发现这种错误首步。

用户同意将该条**从训练候选中排除**。新派生文件为 `data/review/v4_sft_paths_curated_v1/sft_candidates_213.jsonl`，构成如下：

| 来源 | 保留条数 |
| --- | ---: |
| 原 V3 已审轨迹 | 58 |
| V4 模型搜索轨迹 | 114 |
| V4 助理编写的参考轨迹 | 41 |
| **合计** | **213** |

输入、输出哈希以及排除的 task ID 记录在 `artifacts/dataset_manifests/v4_sft_paths_curated_v1.json`。脚本 `scripts/curate_v4_sft_paths.py` 会检查原始 214 条文件哈希、错误首步与正确最终答案的特征，并确保只去掉一条、其余记录原样保留；重复运行不会覆盖不同内容。

**状态仍是候选集，`train_ready=false`。** 对一条轨迹的排除决定，不等于其余待审轨迹或整个 SFT 集已获最终训练批准。41 条参考轨迹也不能被写成 4B 模型自行搜索成功的结果。原始 pass@8、成功题数和搜索轨迹数均不因这个筛选动作而回改。
